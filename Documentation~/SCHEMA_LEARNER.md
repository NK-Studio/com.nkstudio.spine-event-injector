# 스키마 자동 학습기 — `tools/schema_learn.py`

> 작성 2026-11-08 · 목적: Spine 4.0~4.3의 버전마다 `.spine` 스키마를 사람이 바이트를 읽지 않고 만든다.

## 1. 원리

1. **같은 내용의 표본**: 같은 spineboy JSON을 각 버전 CLI로 가져와 프로젝트를 만든다(`research/versions/`). 런처가 `-u <버전>`으로 그 버전을 내려받아 실행한다(이 Mac에서 4.0.64~4.3.26 확인, 3.8은 x86 런처 문제로 불가).
2. **정답 목록**: 이미 해독한 버전 표본을 끝까지 읽어 문자열 집합, float 비트 패턴 집합, 클래스별 객체 수를 만든다.
3. **후보 점수**: 새 버전 표본을 시작 스키마로 읽다 막히면 후보를 만들어 각각 끝까지 다시 읽고, 오류 지점 뒤에서 읽힌 값이 정답 목록과 맞는 정도로 점수를 매긴다(정답 문자열 +3, 정답 float +2, 깨진 문자열·NaN·말이 안 되는 float −4 …). 진행 바이트는 1점 이하로만 반영한다.
4. **후보 종류**
   - 모르는 필드: 다른 버전 스키마의 같은 클래스·같은 태그 타입(우선), V·F·S·O·N·LO, 선언 클래스가 있는 T, 꼬리 필드 수 조정
   - **직전 필드 타입 교체**: 같은 태그가 다시 나오면(`d8` 등) 직전에 읽은 필드의 타입이 틀렸을 가능성이 크다
   - 모르는 클래스 번호: 다른 버전 스키마의 같은 번호 클래스(우선), 새 클래스(종류 × 표). 250 초과 번호는 앞선 결정 오류로 보고 되돌린다
   - 역참조 클래스 불일치: 여러 클래스를 한꺼번에 다른 표로(대상 번호가 맞아떨어지는 조합), 선언 타입 교체
   - 이미 아는 클래스의 형식 교체(`defvtx`↔`defvtx0`, `farray`↔`rfarray`)
   - 타임라인 종류 배치, 대상 슬롯(`*A`)의 «필드 수:첫 태그» 판별
5. **근거가 약하면 두 단계 내다보기**(최고 점수 < 1.5 또는 1·2위 차 < 0.5), **막히면 되돌리기**(직전 결정의 다음 후보).
6. **완료 판정**: 끝까지 읽힘 + 다시 쓰기 = 원본 + 클래스별 객체 수 비교 보고. 그다음 주입 판정은 **그 버전 CLI 자신**으로 한다(`--spine-version <버전>`).

에디터 프로그램은 열거나 풀지 않는다. 저장된 데이터와 CLI 결과만 쓴다.

```bash
python3 -I tools/schema_learn.py --ref research/versions/sb-4.2.43.spine --ref-schema poc/schema/4.2.43.json \
    --start poc/schema/4.2.43.json --prior poc/schema/4.0.07.json \
    --target research/versions/sb-4.2.00.spine --out /tmp/4.2.00.json --steps 150
```

4.3 정식의 구조와 옵션(`groups`, `tl_refs`, `curve_cond`, `root_pad`)은 `FORMAT_NOTES.md`의 «4.3 정식»에 정리했다. 학습기는 앞부분(Project·Skeleton·뼈·제약 필드)을 자동으로 맞췄고, 첨부 묶음·키 곡선 규칙처럼 빌드 사이에 바뀐 구조는 표본 바이트를 비교해 사람이 계기를 잡았다.

런처에 없는 버전: 4.0.00~06, 4.0.42, 4.1.12, 4.2.05, 4.2.07, 4.2.10, 4.2.16, 4.2.21, 4.2.30, 4.2.41, 4.3.24. **그 밖의 4.0.07 ~ 4.3.26 전 버전(표본 144개)이 «끝까지 읽힘 + 다시 쓰기 = 원본»이다.**

**처음 판정이 들쭉날쭉했던 이유**: 버전 차이가 아니었다. 같은 버전이라도 표본마다 **필드 쓰는 순서가 달라지고**(해시 순서로 보임) 그래서 중복 태그 키(`d0`, `t4` …)와 *A 슬롯의 «첫 태그»가 표본마다 달랐다. 또 첨부 클래스의 필드 35(값 0)가 기준 표본에서는 보이지 않았다. 고친 것:
- 4.2.00·4.0.64·4.2.43 스키마의 첨부 클래스에 `35`, `d0`, `t1`, `t4`, `t5`(와 그 슬롯 선언) 보강
- *A 슬롯 판별: «필드 수:첫 태그»가 없으면 필드 수만으로 하나로 정해질 때 그 클래스를 쓴다

예전 계열 표(A~E)의 A(4.0.x)·B(4.1~4.2.00)는 같은 `4.2.00` 스키마로 읽힌다. `4.0.07.json`은 예제 파일용으로 남긴다.

## 4. 스키마 고르기

`poc/schema/*.json`마다 담당 포맷 목록(`formats`, 없으면 파일 이름)을 둔다. 파일의 포맷 문자열에 해당하는 스키마를 차례로 실제로 읽어 «끝까지 읽힘 + 다시 쓰기 = 원본»인 첫 스키마를 쓴다. 경계 탐색 결과로 `4.2.00.json`은 4.0.07~4.2.20, `4.2.43.json`은 4.2.22~4.2.43을 담당한다.
